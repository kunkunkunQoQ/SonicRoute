# 分版本内存优化方案

状态：仅设计，不执行。没有调整缓存上限、合并服务、改变回收策略或运行新一轮内存基准；不预设内存下降百分比。商店使用 Full，Lite 与 Legacy 独立构建。

## Full

已有机制：手机服务按需创建，隐藏/关闭手机面板时停止其媒体、RTT、目录等待；活动音频和虚拟屏独立继续。目录 LRU 最多 4 份、元数据/PNG 估算目标 8 MiB，图标共享懒解码。最后 UI 关闭后，PC 图标保留 32 个热项。

拟议步骤：

1. 只在发现具体残留时，复用既有窗口关闭入口，解除结束任务的事件、封面、列表和待派发快照引用。
2. 若受控快照证明解码图片是主要保留项，再在现有缓存加入字节预算，优先淘汰无可见消费者的图片；保留目录元数据和磁盘缓存，重开只解码可见项。

不能释放：活动手机采集/播放、PC→手机路由、虚拟屏和必要连接。共享手机助手属于后续架构设计，本方案不让空闲助手长期保活，也不进行全进程工作集强制裁剪。

## Lite

已有机制：编译排除手机窗口/XAML、AndroidAudio 依赖和工具，运行时不初始化手机服务。PC 图标后台按需加载，缓存有上限，最后 UI 关闭后保留 32 个热图标。

拟议步骤：

1. 检查已关闭窗口和折叠设备区的行模型、图片、事件引用，仅修复能确认的残留，继续复用与 Full 共用的生命周期。
2. 仅在托盘状态快照证明缓存占用明显时，小幅调整既有图标预算，同时比较重开延迟，防止反复提取 EXE 图标和重复 I/O。

不能释放：托盘、已启用快捷键/自动化以及必要音频会话和设备通知。不增加“空手机服务”或额外后台清理器。

## Legacy / .NET Framework 4.8

已有机制：复用 PC UI/Core 源码，不编译手机模块；COM 枚举、监视器、进程快照和窗口事件具有既有释放入口。

拟议步骤：

1. 核对短期枚举对象、已结束音量监视和窗口订阅是否到达既有释放入口；发现具体残留后只修其所有者，不复制独立生命周期实现。
2. 复用共享图标缓存与关窗裁剪，保持 net48 API 兼容；不添加周期 GC、强制换出或新的后台回收服务。

不能释放：仍被音频会话或消费者使用的 COM/音量订阅，托盘、快捷键、自动化。Legacy 单独验证，不能沿用 Full 的内存结论。

## 后续执行前的最小验证设计

每个版本分别记录正常 EXE 的启动后、开关 UI 10 次后、仅托盘时的 Private Bytes、托管堆、句柄和重开延迟；Full 增加活动音频/虚拟屏下关窗且连接继续的场景。预算调整同时比较保留量与重开成本。工作集瞬时下降不等于释放，组件累计分配也不等于常驻内存。

只在发现持续增长、具体残留或明确回退时扩大跟踪；本文件不授权执行这些测量或修改。
