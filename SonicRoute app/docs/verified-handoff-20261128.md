# SonicRoute 双端交接 · 2026-11-28

Windows Full 的「设备 → 连接设备」提供 Android 和 AirPlay 两个入口。Android 页内先列出 App 的「粘贴邀请」「查找附近手机」，下方是无线调试的二维码、配对码和直接连接。小窗可以滚动到直接连接。刷新页面保留正在使用的二维码。两种连接共用设备档案，合并档案前要求两端完成身份证明。Lite 继续用于不需要手机模块的场景。

Android 的声音、设备、电脑、自动化和设置五页共用主题和导航。首次为第三方应用选择输出时要明确选择物理设备。媒体通知访问、允许电脑控制播放器和每次屏幕共享由手机分别授权。原生输出与按应用捕获分别呈现。

## 已有验证

- Windows x64 Full 和 Lite 均已构建并实际运行。系统 UI Automation 验证了真实音频会话音量写入、回读和恢复。Full 额外覆盖连接页平台选择、键盘焦点、空输入拒绝和配对码保护。桌面功能页的截图使用隔离设备夹具。
- 小米 13（Android 16 / API 36）与 Windows 在真实家庭局域网完成配对、双通道身份合并、切换和回网重连。手机实际离开并返回 Wi-Fi 后，Windows 两次状态观测间隔为 2.303 秒，原进程继续连接。
- Windows 向蓝牙 A2DP 输出写入 38,400 个双声道帧。反向捕获从独立第三方播放器取得非零 PCM，Windows WASAPI 消费 147,840 个采样。MT 播放实测 WAV 时，Shizuku Root 将原生输出从蓝牙分别切到听筒、扬声器并恢复；直接 Root 验证了蓝牙至听筒的往返。
- 两端在受限的 SAF 测试目录往返传输 1,048,593 字节并重新打开校验哈希。Windows 两次单独操作暂停并继续手机测试 WAV，手机实播状态、回调、权限开关恢复均经验证。
- Android 中英文、深浅色、横屏、1.3 倍字号及主要路由与规则对话框均有物理手机原图。媒体和应用目录按需加载。应用新建、暂停和删除测试规则后回读了原规则集。

## 剩余验收及下一步

| 范围 | 续测方法及通过条件 |
| --- | --- |
| 已连接的真实界面、读屏 | 两端保持同一已认证会话，重新定位选中的设备卡，核对电脑页的在线状态与实际音量，再抓取两端原图。补抓受控 WAV 播放页。用 TalkBack、Narrator 和中文输入法手动走一遍操作顺序。 |
| 第三方音量、同一轨道多路输出 | 在可还原测试设备上用第三方播放器、物理输出及外部回录核验不同响度和恢复。小米已测后端没有可靠的第三方独立音量读回及恢复。保留手机系统声音助手入口，同一第三方轨道双物理输出尚待核验。 |
| 后端及外设 | 以普通权限、Shizuku Shell、Shizuku Root 和直接 Root 分别启动，播放中撤权再恢复。在 API 29 和其他 ROM 重测，逐项接入 BLE/SCO、有线、USB。记录实际音轨、端点和回读。 |
| 稳定性、功耗、时延 | 保持已配对的两端跨多小时运行，记录断线次数、进程内存、CPU 与恢复。拔电后测完整连续息屏，记录每次屏幕被唤醒的原因。声学端到端与连续画面延迟需物理回录或同步高速相机。 |
| 剪贴板与系统限制 | 选用两端原剪贴板为空的专用档案，验证双向纯文本、失焦撤权和清理。此次真机剪贴板已有内容，按要求跳过。单次 App 投影是查看功能。交互虚拟屏及定向输入由已绑定的有效 ADB 提供。 |

Android 源码目录内运行 `gradlew.bat :app:assembleDebug :app:assembleRelease :app:lintDebug :core:test`。Release 使用项目原有的未签名构建方式。Windows 从仓库根运行 `Native/Build-Product.ps1 -Edition Full -Architecture x64` 和 `Native/Build-Product.ps1 -Edition Lite -Architecture x64`。协议、字段约束及黄金向量位于 [SRAP 文档](protocol.md) 和 [协议样本](protocol-fixtures/)。
