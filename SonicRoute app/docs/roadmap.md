# 分阶段开发与验收

每阶段开始前核对 Windows 的当前 HEAD/差异、Android 上一阶段的提交及实测缺口。完成后更新 `HANDOFF.md`，记录实际构建、设备、成功、失败与待测项。Windows 只在该阶段需要共享端口或接入功能时修改。所有阶段均以真实结果启用能力，夹具只用于证明对应边界。

| 阶段与依赖 | 交付工作 | 出口验收 |
| --- | --- | --- |
| **0 · 工程基础** | 建立独立项目、依赖边界、四后端的检测与状态页、规范、兼容清单和本地交接。 | Wrapper 构建 debug APK，安装后单机启动，用可观察的普通、未授权、不可用、拒绝、成功或失效状态验证有证据的路径。检查 JVM 状态转换及依赖图，核对其他能力仍待实现。 |
| **1 · Windows 共享端口**，依赖 0 | 从 `PhonePreview`、`AndroidConnectionManager` 和现有设备操作整理最小可用的产品端口。原代码通过 ADB 适配器保留工作流。加入档案别名与原子迁移的隔离夹具。 | 原 Full 走同一组连接及业务回归，覆盖二维码、码配对、直连、换端口、旧 USB 档案、双传输、手动断开、取消配对及移除。客户端不会接错设备。v1–v3 数据、未知字段和路由键回读一致；Lite 验证仍排除手机功能。 |
| **2A · App 配对与协议**，依赖 1 | 实现 NSD、连接生命周期、TLS 信任、Android Keystore、Windows 保护存储、编码、版本/能力协商与端到端取消。 | Kotlin/C# 读写黄金报文一致。双机或隔离两端验证合法配对、指纹错误、过期/重放、未信任端访问、断线、版本无交集、撤销、网络切换和重连。包捕获确认只有 TLS、NSD 无秘密，结束配对后关闭专用监听。 |
| **2B · 档案统一和 Windows UI 接入**，依赖 2A | 在现有添加页挂 App 方式。实现 ADB/App 共存绑定和档案级连接选择、迁移、回退。 | 一台手机用 App、ADB Wi-Fi、USB 交替时只有一条设备档案，原名称、固定应用、音量和路由都保留。同型号两台、冒名地址、旧代次和密钥丢失均拒绝误合并。设备页、画布、伴随窗从同一档案快照变化；已有 ADB 在无 App 时照常使用。 |
| **3 · 本地可用音频与设备**，依赖 0，可与 1–2 独立验证 | 用公开 API 实现本地音频设备、系统媒体音量、自有轨道增益、首选输出及真实回读，接入蓝牙权限和系统配对入口。约束应用目录可见性。 | 断开电脑仍可独立运行。在真实设备上插拔有线、USB，切换扬声器和实际蓝牙播放目标；验证真正出声、回读正确、权限拒绝和设备丢失。连续启动与停止释放 AudioTrack、路由监听及所有临时资源。 |
| **4 · 双向音频与特权后端**，普通双向子任务依赖 2B、3；增强子任务在普通链路之后 | App 到 Windows 先接公开捕获和媒体控制，PC 到 Android 接自有轨道。按后端分别实现和试验第三方逐应用音量、路由、独占、媒体目录和输出控制。有必要时再引入官方 Shizuku UserService。 | 测 API 29/新版、同/不同用户、拒绝捕获的内容、多个应用、整机、切断/重连、Shell/Root 和非 Root。逐应用录音确认无串音，真实目标音响确认播放。在系统确认输出前保持来源播放，撤权或失败后恢复已经改变的状态。证据缺失的 ROM 或动作显示不可用。 |
| **5 · 显示、输入、文件、剪贴板**，依赖 2B，音频共享视图依赖 4 | 先按公开 API 和用户授权实现文件及投屏；再按实际能力实现虚拟显示、输入、剪贴板和复用已有 Windows 行为。 | SAF 范围、传输校验和、取消的临时文件、剪贴板双向/防回环/后台隐私、旋转/窗口大小、镜像授权撤销、独立显示和实际输入验证。ADB 旧功能再做针对性复测。 |
| **6 · 本地自动化与交付**，依赖 3；每条规则另依赖对应已验收能力 | 事件触发、规则编辑与本地持久化、权限及冲突守卫、启动和耗电实测，完成必要的 UI 和无障碍。 | 脱离电脑运行规则和退出重进，重复事件幂等；撤权时暂停正确动作，用户重新激活后才恢复。声卡/设备变动、重启、Doze、前后台和连接共存时验证。确定发行签名与版本矩阵后构建发布候选。 |

## 统一验证准则

- 各条跨平台能力至少验证同一操作在 App 与 ADB 的入口、选择、进度、成功判据和错误语义。两种方式能力相等时操作等价，差异只能来自实际 OS、设备、后端授权、协议版本或资源范围。
- 真实验收记录系统版本、ROM、权限后端、连接类型、使用设备与复现步骤。没有声音、画面、文件或系统状态的回读，操作保留进行中或错误状态。
- 资源验收执行启停、权限撤销和并发短测。关闭后检查观察者、socket、前台服务、编码器、文件句柄及恢复租约已释放。仅修改一个模块时先做它的必要检查。
- 性能至少记录同一设备、同一构建场景下的冷启动 `am start -W` 多次计时、静置 CPU/唤醒和活跃媒体内存。阶段 0 的单次启动只作为首次证据。量化目标在得到首份可复现基线后设定。
