# 性能基准测试规范

适用 BenchmarkLab 1.2 与随附性能观察室。产品功能正确性、性能结论、工具自身正确性分别留证；只运行本次改动需要的检查。目录和清理约束见 [ARTIFACTS.md](ARTIFACTS.md)、[CLEANUP.md](CLEANUP.md)。

本规范供 AI 执行。先读 [AI_TESTING.md](AI_TESTING.md) 的三模式决策和功能路由，再按本文件核对测量方法与验收；不要把全量入口当作每轮必跑要求。

## 1. 测试前

1. 读取根本地 `AGENTS.md` 和 `AI_CONTEXT.md` 顶部快照，确认业务树。根旧工作区的业务 WIP 不作构建输入，不覆盖、清理或回滚。
2. 记录目标路径、EXE / 伴随程序集哈希、源码提交及未提交差异、工具版本、运行时、系统和场景参数。不要拿旧 EXE 代表新源码。
3. 先用 `plan` 查看选中场景、预热、测量、轮次、执行顺序和桌面影响；优先指定本次需要的场景。预估不含启动、就绪、清理和负载超时。
4. 保持电源、设备、应用负载和目标配置一致。不要为制造安静环境擅自退出用户软件、关声音或改系统设置。
5. 同一目标先做 A/A 重复性对照，再做 A/B。最终性能结论至少三轮；低闲时 CPU 建议先使用 30 秒窗口，根据 A/A 和波动决定是否延长，不以短冒烟结论替代。

## 2. 按改动选检查

| 改动 | 必要检查 | 扩展条件 |
| --- | --- | --- |
| 工具计算、协议、采样或清理 | 隔离 Release 构建、`verify`；涉及真实采样时使用自建进程 | 新失败、原生行为变化或尚未解决的问题 |
| 报告数据 / AI review / 状态 | `Viewer/data.test.cjs` 与报告 CLI 专项；浏览器检查验证实际 CLI 创建报告及页面交互 | 新报告格式、review 校验或报告页面行为变化 |
| 成品报告样式 / 交互 | 浏览器打开实际 CLI 生成的报告，检查桌面与手机尺寸及必要截图 | 溢出、无法操作或可读性问题 |
| 产品模块 | 对应产品功能检查 + 对应基准场景 | 只有明确需要整版性能时运行整版基准 |
| 文档 | 命令和路径核对 | 文档涉及新行为时执行对应入口 |

通过后停止扩测。不以堆叠测试项数表示质量，不因工具升级重复产品三运行时全套。

## 3. 测量协议

- A/B 逐轮交换先后顺序；同场景的 A 与 B 相邻运行。历史基线采用独立样本比较，不称配对。
- 单轮预热与测量分开；预热不算稳态 CPU。启动 `WaitForInputIdle` 只是输入队列代理，不能称 WPF 首帧或数据就绪。
- CPU 按端点累计时间 / 实际窗口比较；100ns 是接口表示单位，不保证同等精度。原 5% 相对阈值、30ms 绝对保护值保留。非零但低于绝对保护值的变化仍为不确定。
- 资源均值使用采样时间的梯形加权；百分位和离散程度仍描述已采集样本。工作集峰值是进程生命周期峰值，包含预热。
- 记录实际采样间隔、最大间隔、延迟区间覆盖时长。大于 `max(3 × 请求间隔, 100ms)` 的区间为延迟；延迟覆盖超过窗口 20% 时禁止作比较门禁。这是工具质量策略，不是统计学通用阈值。
- 比较区间采用配对差值 t 区间，或历史样本 Welch-Satterthwaite 区间。临界值对自由度向下取整、30 以上保守使用 30。区间是描述性、逐指标的；不证明因果、不消除系统噪声，也不作多重比较校正。
- Schema 3 基线绑定协议修订、有效时长、预热、采样间隔、场景及 generic 启动参数。旧基线可读；缺协议或参数不一致时，不能作为新协议门禁。
- 单场景三轮只是最低重复性证据，不承诺统计功效。区间跨门限、缺数据、失败或波动未收敛，不得显示 PASS。

参考：[NIST 两样本 t 与 Welch-Satterthwaite](https://www.itl.nist.gov/div898/handbook/eda/section3/eda353.htm)、[NIST 均值置信区间](https://www.itl.nist.gov/div898/handbook/eda/section3/eda352.htm)。

## 4. 隔离与副作用

- SonicRoute 场景使用独立数据目录、实例身份及服务端 PID 就绪确认；禁止复用用户配置。禁用自动更新、自动启动和托盘滚轮，音频写入动作只针对随机不存在应用。
- 自建进程归属 Job；采样取消后等待采样任务退出，再释放句柄和进程。Attach 进程禁止 Kill。
- UI、前台、全局快捷键场景须显式 `--allow-desktop-interaction`。`generic_process` 按目标自身启动逻辑运行，不提供 SonicRoute 隔离保证。
- 测试不得按进程名批量结束用户实例。不得用临时恢复/隐藏用户配置的方式替代真正的实例隔离。
- 工具只在执行期间采样；成品报告读取自身内嵌数据并响应用户筛选、指针与尺寸事件，不新增后台轮询、常驻服务或定时刷新。

## 5. 可视化验收

- 完整对比、单目标汇总、逐轮证据与元数据可读；失败、未知枚举、缺失值和不可比证据不会变成绿色通过。
- 确认退化不会因其他场景不确定而消失；选择成功轮次后，整体失败和失败定位仍可查。
- 示例始终显著标为合成；报告展示必须保留标识。示例不得用于产品性能结论。
- 图表分别展示单核 CPU 百分比、私有内存、工作集；各轮按相对起点对齐，不暗示同时运行。单轮筛选不产生统计结论。
- JSON 文本不能注入 HTML；无效输入保持原数据；旧报告缺样本时给出说明，不伪造曲线。
- 成品报告只读取其内嵌数据；检查页面不得引入上传、远程字体、分析脚本、持久缓存或后台轮询。

## 6. 最低留证与结束条件

保留命令与退出码、构建/验证日志、输入哈希、逐轮结果/时间序列、负载证据、协议和环境、桌面/手机截图（涉及页面时）、清理收据及交付哈希。中途失败仍保留已有证据。

退出码：0 表示比较未检出超阈值退化（run 仅测量完成）；1 为确认退化；2 为参数错误；3 为执行失败；4 为不确定 / 不可比；130 为取消。清理失败必须单独记录，不声称已清理。

必须明确未测的真实音频写入、物理鼠标、OSD、混合 DPI、Explorer 重启、Win10、原生 ARM64、商店安装与整版性能。工具自检和两秒冒烟不等于产品性能改善。
