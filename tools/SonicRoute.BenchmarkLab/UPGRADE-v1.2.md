# BenchmarkLab 1.2 升级设计与范围

## 面向的工作流

先预览 → 选择本次改动相关场景 → 隔离构建 / 执行 → 核对采样与负载 → 浏览器复查逐轮数据 → 留证与清理。复杂性能判断由主代理验收；独立文档或只读清单可按项目授权交给轻量子代理。

## 实施

1. `plan` 不启动目标，预览有效场景、预热 / 测量 / 冷却时间、轮次顺序、桌面影响及短测限制；`--scenario` 支持逗号分隔，按输入顺序执行并拒绝重复 / 未知项。
2. A/B 同场景相邻测量并逐轮交换先后顺序；原始数据、实际窗口和每轮状态保留。资源均值按实际采样时间加权，记录采样间隔、采样读取耗时与延迟质量。
3. 统计区间结构化保存方法、样本数、标准误、自由度、上下界和门限。历史样本使用 Welch-Satterthwaite 自由度。原门限不变。
4. Schema 3 基线绑定测量语义和场景参数。SonicRoute 多文件版本也记录相邻 DLL 哈希，避免只认 apphost 而漏掉实现变化。
5. compare/run 输出 AI review 模板与只读上下文；AI 直接读取原始报告并填写 `ai-review.json`。执行 `report --input <报告目录> --finalize --json` 校验后生成内嵌页面、脚本、测量数据和 AI 总结的 `report.html`，可离线打开，无需网页服务。
6. `report --input <历史报告目录> --json` 可先为已有报告目录准备报告视图；加入 `--finalize` 才会要求完整有效的 AI review 并完成总结。最终报告保留失败 / 不确定状态与合成数据身份，筛选仅影响显示。
7. 统一验证入口将编译、探针、沙箱和浏览器配置放进本轮隔离目录；持续保留报告和清理收据。归属标记和路径边界校验阻止误清理其它材料。
8. 正确性检查提供专项 / 轻量 / 全量三模式，专项细分 CPU、统计、采样、协议、报告、沙箱、清理、进程生命周期与网站数据 / UI。性能命令也提供三模式，专项按已实现功能映射选择，轻量明确是短冒烟，全量覆盖 12 个隔离场景。AI_TESTING.md 给出选择决策、各功能既有检查索引、副作用边界和停止条件。

## 兼容性与边界

compare/ab、run、baseline、scenarios、verify 与既有报告名称保留，新增 plan 与单目标 report.html。工具仍是 NET8 x64，产品版本 / 运行流程不变。旧基线继续读取，跨新旧协议不判通过。旧报告中的实际缺项显示缺失。

成品报告使用鼠尾草绿、米白和轻量曲线，支持桌面 / 手机、键盘操作与减弱动画偏好。报告页面只呈现报告内嵌数据；没有用户上传流程、外部托管依赖或自动轮询本机文件。

AI review 使用 `BenchmarkLab.AIReview.v1`。`review-context.json` 的 `SourceFiles` 每项为 `{Name, SHA256}`，并记录 `ReportSha256`。AI 总结保留该指纹，填写 `Status: complete`、`Author: {Kind: ai, Model: <实际模型名>}`、必需且为 UTC 的 `GeneratedUtc`、中文摘要、场景发现、限制和建议。每次 finalize 追加 `ReviewHistory` 项，结构包含 `Number`、`RecordedUtc`、`ReviewSha256`、`Review`；内容相同不重复追加。修改总结后重新 finalize 会保留既有历史。任何校验失败都不得改变原始测量及判定。

本版没有新增产品内探针、真实音量写入、硬件驱动、首帧测量或整版 CPU 提速声明，也不自动发布工具 / 网站 / 产品。网站先随工具本地交付，后续托管发布需新的明确要求。
