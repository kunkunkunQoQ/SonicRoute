# OSD 音量条性能优化（已实施）

日期：2026-10-01；工作区版本 1.20；基线为阶段 22，当前为阶段 23。

## 实现与作用

| 改动 | 实现 | 预期改善 |
|---|---|---|
| 相同目标去重 | 缓存已应用/活动动画的目标比例和目标身份；同目标输入保留原动画 | 到达 0%/100%、重复结果时，减少时钟替换和动画对象 |
| 绘制前合并 | 只保存最新待绘制比例；按需 Rendering 回调读取最后目标 | 多次输入在下一次绘制前到达时只应用最后一次条更新 |
| 减少过密重启 | 活动动画启动后至少 33ms 才消费下一请求 | 避免 30 FPS 时钟在高刷新率下还未推进就不断被替换 |
| 条过渡期望帧率 | 仅 90ms 条动画 DesiredFrameRate=30 | 减少条时钟所需更新；不是整窗口或系统实际 FPS 上限 |
| 复用缓动 | 冻结的共享 QuadraticEase；注册事件委托在构造时创建一次 | 避免每次过渡创建缓动、每次订阅创建方法委托 |
| 微小变化直接应用 | 布局后的真实轨道宽度 × DpiScaleX × 比例差 < 1 物理像素 | 无明显视觉位移的变化不创建动画；终值仍准确 |
| 生命周期清理 | 隐藏/普通通知/移除音量树/退出取消待请求、移除活动时钟并重置身份 | 避免旧请求回写、空闲订阅和无活动时反复移除时钟 |

百分比、图标和静音说明仍在输入结果到达后即时更新。条只在首次显示、目标切换、系统动画关闭、Tier 0 及开关通知时直接应用终态；普通连续变化通过上面的合并/过渡路径。

请求 B 尚未绘制又收到活动目标 A：取消 B，保留向 A 的原动画。旧动画完成时若有新目标排队：只清旧时钟，保留新请求。回调用动画代际防止旧 Completed 清掉新时钟。

## 开销边界

Rendering 只在有待绘制目标时订阅，处理或取消后立即解除；若刚启动的活动动画尚不足 33ms，订阅短暂保留至可处理的绘制。没有常驻 Rendering 订阅，也没有新增计时器/音频探针。没有输入后只剩原 90ms 条动画和原 OSD 淡出流程，完成后清理时钟。

WPF 的 [Rendering 回调在布局后、绘制时触发](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/graphics-multimedia/how-to-render-on-a-per-frame-interval-using-compositiontarget)，用于消费已经合并的条目标；它会带来短暂回调成本，因此必须按需解除。仅修改 ScaleTransform，不在回调里调整窗口几何或强制 UpdateLayout。

[DesiredFrameRate 是动画的期望帧率](https://learn.microsoft.com/en-us/dotnet/api/system.windows.media.animation.timeline.desiredframerate?view=windowsdesktop-10.0)，实际表现受渲染负载和刷新率影响。条过渡的帧数会减少，少数设备上可能显得更有阶梯感；原淡入淡出时长、其他控件/窗口动画与文字即时更新保持。

音量条启用时仍有额外控件、文字排版及更高的窗口区域，优化不保证 CPU 与关闭时完全相同。快速面板电平仍是原 33ms 采样/2s 扫描和原排除范围。
