# 命令行直接执行自动化规则

适用于 v1.20 的 Lite 和 Legacy；短命令从阶段 27 起提供。

## 基本用法

SonicRoute 已运行时，在任意目录直接执行：

```powershell
sr "规则名称"
sr "规则ID"
```

首次正常启动新版会自动登记用户级命令入口，请关闭并重新打开终端（Windows Terminal 需关闭旧进程，单开新标签可能仍沿用旧环境）。之后无需切换到软件所在目录，不需要管理员权限。登记只向用户 PATH 追加 `%LocalAppData%\SonicRoute\Command`，保留其他路径；文件内容及 PATH 未变化时不会反复写入。

短命令直接连接运行中的实例，不会重新启动 SonicRoute；软件未运行时返回退出码 6。同时运行 Lite 和 Legacy 时默认使用 Lite，可以指定：

```powershell
sr --legacy "规则名称"
sr --help
```

参数使用规则的完整名称或 JSON 内的 `Id`，忽略大小写。Id 优先匹配，也支持 GUID 的带连字符形式。名称重复时拒绝执行，请改用 Id。名称含空格时加引号，一次调用一条规则。

这是直接执行入口，无需满足快捷键、应用、定时或启动条件；关闭自动触发的规则也可以执行。保留全部步骤、顺序和延时，失败后继续后续步骤，不修改规则的启用状态、快捷键或定时执行记录。

命令交给同一用户、同一登录会话的现有实例，不打开主窗口。收到请求后不会因规则失败而尝试另一个版本；没有重复执行或自动重试。

## 软件未运行时的兼容入口

保留完整程序路径调用，另增加 `-r` 简写：

```powershell
.\SonicRoute.exe -r "规则名称"
.\SonicRoute.exe --run-rule "规则名称"
```

软件未运行时，临时初始化音频与 OSD，执行完成后退出；不会启动托盘、快捷键、自动触发、定时调度或常驻监听，也不会顺带运行其他“SonicRoute 启动时”规则。最后一条 OSD 会按原显示时间和淡出完成后退出；麦克风常驻提示在此模式下临时显示，长期常驻需要正常启动软件。

同一规则正在执行时，重复请求返回忙碌，不排队、不重复运行。不同规则可并发。临时执行进程退出前等待已经接收的其他请求完成。

## 脚本中等待完成及读取结果

短命令会直接等待结果，在 PowerShell 中不再需要 `Start-Process -Wait`：

```powershell
$json = sr "规则名称"
$code = $LASTEXITCODE
$result = $json | ConvertFrom-Json
$result
$code
```

直接保存 JSON：

```powershell
sr "规则名称" > result.json
$LASTEXITCODE
```

输出示例：

```json
{"ExitCode":0,"Code":"ok","RuleId":"示例ID","RuleName":"规则名称","Succeeded":2,"Failed":0}
```

输出的字段和 `Code` 是固定协议；`sr --help` 跟随最近一次正常启动软件的语言，完整程序入口的 `--help` 跟随配置语言。

完整程序入口是 GUI 程序，需要在脚本里等待时仍应使用 `Start-Process -Wait -PassThru`；无控制台的快捷方式调用不会弹出命令行窗口。

| 退出码 | Code | 含义 |
|---|---|---|
| 0 | ok | 全部步骤成功 |
| 1 | step_failed | 至少一个步骤失败，仍执行后续步骤 |
| 2 | invalid_arguments | 参数缺失、混用或格式错误 |
| 3 | rule_not_found | 未找到规则 |
| 4 | ambiguous_rule | 名称或 Id 匹配多条规则 |
| 5 | rule_busy | 同一规则正在执行 |
| 6 | server_unavailable | 现有实例无法连接、通道断开或无法取得结果 |
| 7 | canceled | 程序退出导致执行取消 |
| 8 | internal_error | 执行器内部异常 |

短命令只查找已经运行的实例，每版连接等待最多 250ms；完整程序入口等待启动中的实例最多 5 秒。规则执行没有固定超时，以支持长延时。通道失败不会自动重试或另起进程执行：断开时可能已有步骤执行，调用者应先确认结果再决定是否再次调用。旧版运行实例不支持此通道，需先正常退出旧实例并启动本构建。

规则中的启动程序 / PowerShell 沿用原语义：成功表示已提交启动，不等待所启动程序或脚本自身运行完毕。

## 1.21 工作区补充（开发中）

每个操作步骤可以独立选择“步骤失败后停止”，默认关闭。不勾选时步骤照常执行，失败后继续；勾选时仍执行该步骤，只有它失败才跳过本规则剩余步骤。退出码 1 仍表示步骤失败，结果 JSON 增加 `Stopped`（是否因失败停止）和 `Skipped`（本规则跳过步骤数），原有字段保持。

每条规则的 `⋯` 菜单可复制按 ID 定位的短命令；新增“执行另一条规则”操作，等待目标完成后继续，调用步骤失败时按该步骤的选择决定是否停止。详见 [1.21 开发功能说明](automation-convenience.md)。
