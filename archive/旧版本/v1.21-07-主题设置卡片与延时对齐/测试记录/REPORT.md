# 1.20 与当前 1.21：界面与资源对比

2026-10-08。应用户出门前尽快交付的要求，完成当前 OSD 配对后停止，未继续原计划的 OSD 第二、三轮及补采。

## 结论

- 有效静置样本的 CPU 均接近零，未证实当前版本有明显 CPU 改善。
- 设置页私有内存中位值约增加 4.77 MiB，工作集约增加 8.43 MiB，托管堆约增加 2.85 MiB。新 UI 有内存开销。
- 自动化列表托管堆约增加 8.5 MiB；旧版私有内存波动很大，不能从短样本认定长期内存改善或泄漏。
- OSD 只有一轮，旧版遇到外部高负载，不能据此判断 CPU 效率提升。

## 有效静置结果

各值先取单轮样本均值，再取有效轮次中位值。CPU 为全机 16 个逻辑核心归一化百分比；内存为 MiB。两轮中位值取两者平均。

| 场景 | 有效配对轮数 | CPU 1.20 → 1.21 | 私有内存 1.20 → 1.21 | 工作集 1.20 → 1.21 |
| --- | --- | --- | --- | --- |
| 主题页静置 | 2 | 0.0374% → 0.0342% | 140.92 → 141.86 | 151.61 → 157.28 |
| 设置页静置 | 3 | 0.0748% → 0.0716% | 141.81 → 146.58 | 162.50 → 170.93 |
| 50 条禁用规则静置 | 2 | 0.0634% → 0.0586% | 143.50 → 159.57 | 159.94 → 166.63 |

这些 CPU 差值处于近零样本的波动范围，不作为优化幅度。自动化旧版第一轮私有内存范围 92.88–176.23 MiB，内存表格必须结合原始范围阅读。

## 采样条件与排除项

- 同机、同一 Release/WPF 驱动、.NET 8.0.30、16 逻辑核心、WPF 渲染 Tier 2。
- 窗口目标 920×620 DIP、位置 20,20，清除键盘焦点、指针放在窗口外。三轮次序交替，第二轮先当前版。
- 静置每次预热 10 秒、采样 30 秒；OSD 预热 15 秒、采样 60 秒，请求合成音量更新 15 Hz，不调用实际音量写入。
- 主题第一轮旧版位置实际为 766.67,320 且指针不在窗口外，整组配对排除；有效轮次为第二、三轮。
- 自动化第三轮当前版整机 CPU 均值 35.37%、P95 40.25%，超过批次外部负载阈值，整组配对排除；有效轮次为第一、二轮。
- OSD 第一轮旧版整机 CPU 均值 28.40%，受高负载影响。实际更新频率为旧版 11.883 Hz、当前版 12.252 Hz；进程 CPU 原始均值分别 0.4192%、0.3727%，仅作记录，不作效率结论。第二轮被中断，不纳入汇总。

原始逐秒样本、各轮均值/最小值/最大值、外部负载与驱动日志在 `raw-results/final-stage43-20261008-01/`，批次摘要在其中的 `progress.jsonl`。

## 来源与隔离边界

基线为 `v1.20^{commit}`：`de1de5a1b9003071bd67a1934f038e1965fdebbd`。74 个项目路径逐一核对，68 个与 Git blob 一致，6 个仅为隔离保护。当前版 86 个项目路径与工作区一致，除同一组 6 个隔离文件外均逐文件 SHA256 相同。详见 `isolation-patches.md`。

两版都跳过真实 App 启动编排，测试配置、规则、日志、语言及命令路径隔离。驱动手动加载资源和窗口；没有完整托盘、热键、自动化调度及音频后台。因此结果只代表这些界面负载，不能解释为正式程序完整后台的资源变化。

真实 config.json 与两份自动化规则的测试前后 SHA256 一致，见 `user-data-hashes-before.json`、`user-data-hashes-after.json`。未执行真实规则、音量/路由写入、自启动注册或结束用户进程。
