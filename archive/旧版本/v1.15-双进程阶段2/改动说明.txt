三、阶段 2 关键设计
- 管道：Req=SonicRoute.Ipc.Req（请求/响应）、Evt=SonicRoute.Ipc.Evt（Backend→UI 事件 + EvtHello 注册）
- 协议：4 字节小端长度前缀 + UTF-8 JSON；IpcMessage{T,Id(int?),P}
- Backend（--service）：单实例锁拥有者、配置权威写入者；快捷键直执行 Core + 事件广播；
  不持有任何 Window/QuickPanel 引用；idle 回收依赖 _ipc.HasUi
- UI（--ui）：连接 → EvtHello → Hello 会话判定（ExistsUi/Replace）→ QueryState 取配置快照 →
  ConfigService.SetSnapshot + 4 个 override（Save/Reset/Export/Import 全经 IPC）→ 订阅事件 →
  启动行为（--panel/--main/按配置）
- UI 关闭 → Backend 继续；UI 重开 → 重连取最新状态
- 单实例：Mutex Local\SonicRoute_9NQZGRTPM1NT 归 Backend

四、本备份前修复的两个 UI 启动根因（重要教训）
1. 协议层 await 死锁：IpcProtocol.WriteAsync/ReadAsync/ReadFullAsync 缺 ConfigureAwait(false)，
   UI 线程 TryConnect 用 GetAwaiter().GetResult() 同步等待写 EvtHello → 续体要回 UI 线程执行 →
   永久死锁（UI 卡"开始连接"、进程堆积、主窗口出不来）。已全部补 ConfigureAwait(false)。
   —— 教训：库级 IO async 方法一律 ConfigureAwait(false)；UI 线程同步等待只允许
   等"不依赖 UI 上下文"的 Task。
2. 事件连接即断：IpcServer.HandleEvtAsync 读完 EvtHello 立即 return，finally 马上注销并
   Dispose 事件管道 → _activeEvt 永远 null（事件广播全丢）、UI 被杀后 _activeUiId 永不清理
   （新 UI 启动 ExistsUi=True 被判定"已有 UI"而退出）。已改为注册后长驻读取循环，
   仅断开（ReadAsync 返回 null）才清理会话。
