# SonicRoute v1.0.5r4 源码说明（带注释）

> 本目录是该版本完整源码快照（已排除 bin/obj 编译产物）。相对 v1.0.5r3 的改动点如下。

## v1.0.5r4 改动点

### 修复快捷键有时识别错误应用（核心修复）
- **问题现象**：全局快捷键（静音 / 切设备 / 音量增减）偶尔操作到错误的应用，而快捷面板 / 概览识别的当前应用是正确的。
- **根因**：
  1. `CurrentAppService.Current`（共享当前应用）经常为 null——它只在面板/概览打开（`SetCurrentApp`）或 **recent** 模式的 1.5s 前台监听时被写入；**last / fixed 模式下或从没打开过面板时一直是 null**。
  2. 快捷键在 `Current` 为 null 时走 `CurrentAppService.Resolve`，而 `Resolve` 的优先级是"**按下快捷键那一瞬间的前台进程**"（有音频即命中）。面板打开瞬间前台正好是用户正在用的应用所以正确；但快捷键按下瞬间前台往往不在目标应用上（刚点过托盘/桌面、后台挂着 Chrome/网易云等有音频应用），就会误命中无关应用 → "面板对、快捷键错"。
- **修复方案**：快捷键在 `Current` 为空时，改为**优先使用 `CurrentAppService.LastForegroundAudio`**（最近有音频的前台应用，由 1.5s 前台监听维护、任意模式都在记录），该应用已退出或无记录才回退 `Resolve`。它与面板/概览同源，比"按下瞬间的前台"稳定得多。
- **改动文件**：`App.xaml.cs`（`ExecuteHotkeyAsync` 的目标解析段）。`Resolve` 本身、面板/概览/托盘逻辑均未动。
