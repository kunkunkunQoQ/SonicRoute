# 1.21 工作区：自动化与音量快捷操作

本页描述开发中的 1.21 源码功能；GitHub 已发布的 1.20 不包含这些新增入口。

## 自动化列表外观与排序

自动化页采用独立卡片：左侧显示操作图标、加粗的**真实规则名称**和操作摘要，中间展示触发方式及应用/时间/快捷键，右侧依次为启用开关、运行、编辑、复制、删除和 `⋯`。例如名为“1”的规则，标题就是“1”，不是步骤序号。长名称和摘要省略时，悬停可查看全文。

“新建规则”位于标题右侧；搜索框带图标和提示文字，状态及触发筛选位于右侧。最右边的列表选项可重置筛选、恢复名称排序、打开脚本文件夹。新建或编辑时，右侧专门显示编辑区；保存或取消后返回列表，恢复原有搜索条件和滚动位置。

拖动规则左侧的点状手柄，松手后保存新的列表顺序；Esc、失焦、离开页面或关闭窗口取消未提交的拖动。筛选时也可在可见规则间移动，其他规则保留相对顺序。顺序按 ID 存于配置 `AutomationRuleOrder`，没有保存顺序时按名称排列；规则改名不改变已排定的位置，新规则排在已有自定义顺序后。

排序只影响展示，不改变自动触发顺序或规则内部步骤的执行顺序。开关只控制自动触发；关闭的规则仍能手动运行。每步“失败后停止”沿用独立、默认不勾选的设置。

卡片、开关、菜单和矢量图标复用深浅主题及强调色。运行中或正在编辑的规则高亮，规则行按 ID 复用；不为每行添加阴影、循环动画或后台轮询。

## 导航图标与规则编辑区

左侧概览、应用、快捷键、主题、设置、自动化、实验设置共用同一导航模板，各有矢量图标；选中项图标使用当前强调色，实验设置仍按原条件显示。

规则编辑区分为带图标的标题、基本信息和操作三个部分。规则名称仍可编辑；触发条件沿用已有快捷键录制、应用选择和定时控件。每个操作为彩色圆角卡片：左侧拖动手柄，中间操作图标和分类下拉，右侧复制及红色删除按钮；参数、延时、每步可选失败停止放在卡片内部。

OSD 主标题和副标题并排；启动程序保留全部/随机模式、文件拖放、启动列表和各文件的打开方式，路径栏增加文件图标。启动列表随可用宽度伸缩，无需固定 520px；默认打开方式没有应用图标时复用矢量占位图标。

拖动、字段写回、复制、保存、执行均复用原有逻辑。切换操作只更新该卡片参数，并从慢刷新集合移除旧下拉；分类配色画刷按深浅模式缓存并冻结，回到自动化页只更新配色，不重建整个编辑器。没有新增轮询或持续动画，也没有测量 CPU/内存变化。

## 搜索与筛选

自动化列表顶部按“规则名称搜索 → 状态筛选 → 触发方式筛选”同一行排列，两个筛选框在搜索框右边。搜索不修改规则，不改变其触发或执行行为；新保存的规则若不符合当前筛选条件，会暂时不显示。

## 复制执行命令

每条规则的 `⋯` 菜单提供“复制执行命令”。使用规则 ID，改名后仍有效：

```powershell
sr "规则ID"
sr --legacy "规则ID"
```

Lite 生成第一种，Legacy 生成第二种。短命令使用已运行的实例；首次启动新版后重新打开终端。正常规则 ID 是 GUID，命令适用于现有短命令入口；非 GUID 的自定义 ID 使用 PowerShell 单引号转义。

## 托盘常用规则

在规则的 `⋯` 菜单勾选“加入托盘常用规则”，随后通过托盘右键的“常用规则”直接执行。取消勾选即移除；名称变化按 ID 关联，删除的规则不会出现在菜单。

收藏与自动触发启用状态独立：已停用的规则仍可明确手动运行。正在运行的规则不能重复执行，结果使用 OSD 提示。收藏保存在 `config.json` 的 `FavoriteRuleIds`，仅打开托盘菜单时按需读取，没有新增定时轮询。

## 音量快速档位

右键音量滑块，选择 25%、50%、75% 或 100%。支持简洁面板顶部和应用行、经典面板，以及完整界面概览/应用页。

档位通过原有滑块处理音量写回、应用行防抖与反馈；不改变滑块所控制的目标。四个菜单项仅第一次右键时创建，后续复用，深浅主题共用样式。

## 失败后停止：可选，默认关闭

每个操作步骤的参数区提供“步骤失败后停止”复选框，**新步骤默认不勾选；旧步骤缺少字段时也关闭**。可以只勾选其中某几个操作。

- 不勾选：该步骤照常执行，即使失败也继续后续步骤。
- 勾选：该步骤照常执行，成功则继续，失败才跳过本规则剩余步骤，不撤销已经完成的操作。
- 编辑、保存、复制步骤或规则、拖动排序和切换操作类型均保留每步选择。

字段为步骤级 `Actions[i].StopOnFailure=false`。先前开发构建中规则顶层的 `StopOnFailure` 已移除，不再影响执行；未设置步骤字段的规则继续执行，保存时写入各步设置。反馈显示成功、失败、跳过数量；命令行 JSON 新增 `Stopped` 和 `Skipped`，原有字段及退出码含义保持。

程序/PowerShell 动作沿用现有“是否启动成功”的判断，未新增等待外部进程退出或脚本退出码检测。

## 新操作：执行另一条规则

添加步骤，在“自动化”分组选择“执行另一条规则”，再选择目标规则。目标按步骤字段 `TargetRuleId` 保存；新操作枚举为 `ExecuteRule=17`，旧 0–16 枚举编号不变。

1. 直接执行目标，不等待其触发条件；已停用的目标也允许明确调用。
2. 等待目标完成，再继续调用方的下一步；双方各自遵守原有步骤延迟。
3. 目标任一步骤失败、目标不存在或正在运行时，调用步骤记为失败；是否停止调用方由这个“执行另一条规则”步骤的复选框决定。
4. 目标内部各步骤自己的失败设置只控制目标规则的剩余步骤，不强制停止调用方。
5. 下拉排除当前规则，保存时拒绝自身及缺失目标；执行时拒绝调用链中的重复规则和超过 16 层的调用，避免无限递归。循环边被拒绝后，各步仍按自己的失败设置处理。

例如：A 先执行 B，再显示一条 OSD。B 失败且 A 的调用步骤未勾选停止时，A 仍显示后面的 OSD；调用步骤勾选后则跳过该 OSD。A 中其他步骤的勾选不会影响本次调用步骤的判断。

## 手工检查建议

- 检查七项导航图标及选中颜色；新建/编辑时列表隐藏，保存/取消后返回列表，筛选条件和原滚动位置保留。
- 检查快捷键/应用/定时触发的字段，OSD 双文本、延时、程序随机模式和逐项打开方式；切换操作类型后参数区、图标及配色应同步。
- 复制、删除及拖动操作步骤后，确认字段值和各步失败停止设置保留；切换深浅主题后返回编辑区，检查文字及卡片配色。
- 检查普通名称、数字“1”、长名称、多步骤摘要及六种触发信息是否显示正确；图标按钮悬停时应显示对应名称。
- 拖动后关闭并重新打开主界面，确认顺序保持；改名后位置不变，列表选项可恢复名称排序；筛选、Esc 和失焦时取消拖动，不应误运行规则。
- 关闭规则开关，确认自动触发停用、手动运行仍可用；运行中按钮不可重复点击，完成后恢复，编辑/复制/删除/更多入口可正常操作。

- 新建多个步骤，确认各步失败停止默认未勾选；只勾选其中一步，保存、重开、复制和拖动后确认各步状态独立保持。
- 用仅显示 OSD 的规则检查收藏、托盘运行、复制命令和规则改名。
- 创建 A 调用 B，B 只显示 OSD；停用 B 后再次运行 A，确认仍可调用。
- 放两个操作未运行应用的失败步骤，再放 OSD；只勾选第二步，确认第一步失败后仍执行第二步，第二步失败才跳过 OSD。全部不勾选时应显示 OSD。
- 勾选一个只显示 OSD 的成功步骤，后面再放 OSD，确认勾选不会阻止成功后的步骤。
- 检查直接自调用不可选择；通过现有规则构成间接循环时应返回失败，程序仍可操作。
- 切深浅主题，右键各类音量条选择档位，检查数字/滑块和实际目标一致。

本轮只完成源码审查与 Lite/Legacy/ARM64 编译，没有运行界面、功能或性能测试；以上是用户可执行的验收步骤。
