# v1.21 隔离测试复现

## 范围

本工具由已授权的 gpt-6-luna 子代理执行；根代理提供 UI 用例模块并复核最终数据。`source/baseline` 来自 v1.20-35，`source/candidate` 为最终 v1.21 的测试副本；其中有启动、音频写入屏蔽和路径重定向接缝，**不能用测试副本替换生产源码**。接缝详情见 GUARD-SEAM-MANIFEST.md。

需要 Windows、.NET 8 SDK/WPF运行时及 .NET Framework 4.8。工作目录可使用当前 `dist/v121-validation-agent/` 或留档 `独立验证/`；构建输出在该目录下的 bin，测试配置只在 bin 对应的 test-data。留档不包含 bin/obj，需重新构建。原始结果路径包含测试时的绝对目录，移动留档后仍保留原始值。

## 构建候选

以下在 PowerShell 7 执行；先将当前目录设置到测试工具目录。输出路径明确使用绝对路径，避免测试产物落入仓库根目录。

```powershell
$testRoot = (Get-Location).Path
$liteBin = Join-Path $testRoot 'bin/lite/candidate'
$legacyBin = Join-Path $testRoot 'bin/legacy/candidate'
dotnet build ./runner/PerfReview.csproj -c Release -f net8.0-windows10.0.19041.0 -p:SourceSide=candidate -o $liteBin --nologo -v minimal
if ($LASTEXITCODE -ne 0) { throw 'Lite test build failed' }
dotnet build ./runner/PerfReview.csproj -c Release -f net48 -p:SourceSide=candidate -o $legacyBin --nologo -v minimal
if ($LASTEXITCODE -ne 0) { throw 'Legacy test build failed' }
```

## 执行单个用例组

示例为存储正确性；每次用不同的输出目录，避免覆盖已有原始结果。

```powershell
$testMode = 'storage'
$liteResults = Join-Path $testRoot ('results/repeat-lite-' + $testMode + '-' + (Get-Date -Format yyyyMMdd-HHmmss))
dotnet exec --depsfile (Join-Path $liteBin 'SonicRoute.deps.json') --runtimeconfig (Join-Path $liteBin 'SonicRoute.runtimeconfig.json') (Join-Path $liteBin 'PerfReview.dll') $liteResults $testMode
if ($LASTEXITCODE -ne 0) { throw 'Lite harness failed; inspect results.json' }
$legacyResults = Join-Path $testRoot ('results/repeat-legacy-' + $testMode + '-' + (Get-Date -Format yyyyMMdd-HHmmss))
& (Join-Path $legacyBin 'PerfReview.exe') $legacyResults $testMode
if ($LASTEXITCODE -ne 0) { throw 'Legacy harness failed; inspect results.json' }
```

Lite 显式使用 SonicRoute 的 deps/runtimeconfig：测试入口自己的 deps 曾无法解析 SonicRoute 1.21，这属于测试启动器问题。生产开发版正常使用自身入口，不需要此命令。

| testMode | 用途 |
| --- | --- |
| storage | 存储10项正确性，含改名失败保护/缓存/目录重建 |
| atomic-conflict | 持续共享锁失败保留旧值、短锁释放后重试成功 |
| ui-v121 | 行复用、名称合并/flush、设备选择保留、规则快照、8行面板与电平清理 |
| indexed-save | 100条规则重读后50次真实文件保存的 CPU/分配/耗时 |
| osd-strict | 可见 OSD 开/关音量条、独立逻辑频率、最终值/隐藏/清理 |

测试入口设置隔离环境变量，并检查 ConfigPath/RulesDir 在当前二进制的 test-data 下。音频及路由 setter 在测试副本直接阻断；没有启动真实规则。自动化 fixture、名称、共享锁只影响生成的测试数据。

**进程退出码0表示工具执行完毕，断言还需检查 `results.json` 的 Pass。** 候选不应有 Pass=false 或 Case=error。例如：

```powershell
$records = Get-Content (Join-Path $liteResults 'results.json') -Raw | ConvertFrom-Json
$failures = @($records | Where-Object { ($_.PSObject.Properties.Name -contains 'Pass' -and $_.Pass -eq $false) -or $_.Case -eq 'error' })
if ($failures.Count -gt 0) { $failures | ConvertTo-Json -Depth 8; throw 'Candidate assertion failed' }
```

## 基线与性能配对

将 SourceSide 改为 baseline，分别输出到 `bin/lite/baseline` 与 `bin/legacy/baseline`，并使用对应的启动路径。基线版本1.20，故意注入的改名写入失败会导致保护断言失败，这是旧缺陷而非工具错误；ReadSnapshot 在基线不存在。

性能组逐个进程运行，构建与测量不并行；同运行时按“基线、候选、候选、基线”顺序配对，至少复测两轮。不要同时跑两种运行时或其他性能工具。CPU阶段没有帧数监视器，逻辑更新频率另测；窗口必须可见且与工作区相交。OSD 的请求输入30Hz实测仅约21.3Hz，不能将 ScaleX 变化次数称为实际屏幕FPS。文件落盘受防病毒/索引/其他IO影响，记录P95/最大值，不只看均值。

最终采信组：formal4 的存储、共享冲突、UI、规则保存与 Lite 屏幕内 OSD；formal6 的 Legacy 完整旧算法最终回归。formal3 的 UI 原始对照仍可用；其较早 AtomicFile 保存性能已被替换。formal4 Legacy 插值及 formal5候选是已撤回中间版本。其余屏幕外/工具调试数据保留供追溯，不能汇入最终收益。

复现会有屏幕内 OSD 的短暂显示，但不会调节实际系统/应用音量或切换音频设备。正式生产入口、真实播放/音频写入、不同显示器/DPI及ARM64真机仍需手工验证。
