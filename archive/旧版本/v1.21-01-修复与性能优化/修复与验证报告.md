实施开始：2026-10-02；实施与验证完成：2026-10-03。v1.21 是本地开发版本，本轮没有上传或发布 GitHub，公开最新正式版仍为 v1.20。

| 其他 | 无会话 AllMuted=false；移除滑块重复峰值刷新；关闭 UI 回收也按120秒/增长阈值判断 | 修正空态并减少重复刷新/强制回收 |

规则保存仍有内存索引维护/排序，不宣称整个 Save 为 O(1)。规则外部监听增加一个 FileSystemWatcher；没有额外定时扫描线程。

保存沿用原来的 OS 写缓存策略，取消本轮初版额外加入的 `Flush(true)` 强制物理同步。初版 Lite/Legacy 重复保存曾出现约 500ms 的尾部延迟，已退回此策略，最终性能只引用退回后的数据。共享冲突只对 Win32 32/33/1175、原文件及临时文件仍存在且没有回滚文件的情况额外重试两次，等待5+15ms；其它错误直接失败。实际等待还受系统调度影响。

`File.Replace` 使用唯一回滚路径：成功后清理；失败且原路径不存在时尝试恢复旧文件，若文件系统仍阻止恢复则保留备份数据。该分支依据 [Microsoft ReplaceFileW 文档](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew) 对1176/1177的部分失败状态设计；未在真实文件系统强制制造1176/1177。持续共享锁及短锁释放回归在隔离目录完成。

电平目标继续包括快速面板中全部合格应用，排除隐藏、静音或无可用滑块的应用。应用设备栏切换保持直接切换。

## 独立测试方法

子代理：gpt-6-luna，极高推理强度。工作目录：`dist/v121-validation-agent`。

- 修改前基线来自 `../v1.20-35-代码审查与性能测试/源码快照`；候选来自当前生产源码。
- 两边测试副本屏蔽 App.OnStartup，配置/规则重定向到各自 test-data；所有音量、静音、麦克风及设备写入口加只在测试副本生效的保护。
- STA Dispatcher 安装同步上下文；不启动原有程序入口/自动化执行；不运行默认会写用户音频状态的 Selftest。
- 空会话用例在两侧测试副本对 Refresh 加 no-op 接缝。保存计数/竞态测试接缝必须在测试清单中列明。
- 构建与测量顺序进行；OSD CPU/分配阶段不挂帧数监视器，帧数另测。记录实际输入频率，不能把请求30Hz当成实测30Hz。

## 功能回归

Lite 与 Legacy 存储10项正式回归通过：失败保护、改名、同名、旧Id文件迁移、删除、深副本、修订/外部修改、目录重建、空会话静音、合并状态读取。外部修改及目录重建约50ms被测试观察到。最终原始结果在 `独立验证/results/formal4/*candidate-storage-full/results.json`。

持续共享锁用例确认：保存抛 IOException（Win32 32），原文件及 Find 缓存保持旧值，不留下临时文件；约10ms后释放锁的用例在短重试后成功保存新值。Lite、Legacy 均通过。最终原始记录中持续锁失败用时24.5/29.0ms，短锁成功用时37.6/87.7ms，包含IO及调度时间；不能把源码等待上限20ms解释成总耗时上限。

两种 x64 运行时 UI 回归通过：100 行运行状态更新全部复用；修改一条规则复用其余 99 行；连续 10 次改名由 10 次保存变成合并 1 次保存，最终值正确；失焦及关闭 flush、设备名称刷新保留设备选择、快速面板 8 行加载、全部合格行采样目标过滤及停用后释放工作线程通过。`GetWatchRules` 在修订不变时 1000 次调用返回同一快照，保存启停变化后正确更新。本轮未执行规则或改变实际音频状态。

Lite 最终 OSD 与 Legacy 恢复原算法后的最终回归均确认：数字77%、ScaleX=0.77、动画及 pending 停止、隐藏和禁用清理通过。Lite 有订阅字段且最终为 false；Legacy 原实现没有该字段，反射值为 null，通过原有 pending/动画/隐藏检查判断停止。

## 性能对照结果

测试机：Windows 11 build 26100，i7-13620H，16 逻辑处理器；Lite 使用 .NET 8.0.30，Legacy 使用 .NET Framework 4.8.9336.0；WPF RenderTier=2。结果是短时间、指定工作负载的进程 CPU 用时及 UI 线程分配，不能推算日常整体占用或长期内存下降。

### Lite 屏幕内 OSD

正式两轮按 ABBA 顺序，窗口在 `(24,24)`，Opacity=1、可见且与主屏工作区相交。每次7秒约149次更新，实际输入约21.3Hz（DispatcherTimer 请求30Hz没有全部送达），两侧实际频率匹配。CPU阶段不添加 Rendering 监视器，逻辑频率单独测量。

| 指标 | v1.20 基线 A / B | v1.21 候选 A / B | 结论 |
| --- | --- | --- | --- |
| 音量条开启 CPU 用时 | 1453.125 / 1171.875ms | 640.625 / 734.375ms | 两次均值下降47.6%，仅代表此屏幕内连续更新场景 |
| UI线程分配 | 2,702,472 / 2,686,128B | 1,986,016 / 1,996,016B | 两次均值下降26.1% |
| ScaleX逻辑改变频率 | 约30次/秒 | 约30次/秒 | 不是屏幕实际呈现 FPS |

音量条关闭时两侧 UI 分配均约1.10MB。原始数据：`独立验证/results/formal4/lite-{baseline,candidate}-osd-onscreen-{a,b}/results.json`。

Legacy 的新插值实验（formal4）CPU均值约617ms，基线约430ms；部分恢复 WPF 的中间版本（formal5）也未证明 CPU 改善。因此最终 NET48 恢复原来的完整96行动画方法块。最终单次回归（formal6）CPU=296.875ms，位于 formal5 基线296.875–437.5ms范围，逻辑改变频率30.02Hz；这是回归证据，**不宣称 Legacy OSD 降低 CPU**。

屏幕外 OSD（formal1/2）、初版22Hz实现、反射错误/监视器污染测量以及已撤回的动画版本仅保留为调试记录，不计入最终收益。

| 指标 | 基线 A / B | 候选 A / B |

| Legacy 每次分配 | 2,701,493 / 2,701,493B | 34,749 / 34,749B |

### 手工验证建议

1. 从托盘退出现有 SonicRoute，再启动上述 Lite，确认界面版本1.21；每测一种版本先退出上一种，避免单实例转发到旧进程。真实功能验证会使用现有配置，涉及规则/名称编辑时先自行复制原配置和 Automation 文件夹。
2. 开启 OSD 音量条，用原有快捷键/托盘滚轮连续调音量，检查数字和进度条一致、松开后不继续移动、到时正常消失；切深浅主题，关闭音量条再重复；数字仍在左侧。
3. 应用/设备名称快速输入，立即离开输入框或关闭窗口，重开检查最终名称；设备改名不应改变所选输出设备。
4. 在自动化页添加一条仅显示 OSD 的测试规则，改名/启停/复制/手动执行，检查顺序和运行按钮；编辑后取消不应修改原规则，保存后重开应保持。常用复杂规则再按原使用方式验证。
5. 快速切换两个应用及输出设备，检查音量/静音详情属于最后选择；在快速面板连续调整，检查行数/图标和滑块正常。
6. 多应用播放时开实时电平，检查有声反馈、静音/隐藏行排除；向下滚动仍保留全部合格应用目标；关闭主题开关/关闭面板后电平停止。
7. 任务管理器用同样的应用、播放内容、设备、开关与操作节奏，对v1.20/v1.21分别观察至少30–60秒，分开记录空闲/开面板/连续OSD；私有内存与工作集分开比较。短测数据不能代替长期真实播放对照。

隔离自动测试工具及复现说明见 `独立验证/复现测试.md`，结果索引和接缝清单也位于该目录。自动测试没有执行真实音频写入，手工测试补充该覆盖。

## 覆盖限制与后续项

这不是整机长期使用/完整功能验收。真实多应用持续播放、设备插拔、音频写入执行链、正式启动入口、不同DPI/显示器及ARM64真机没有完整验证；模拟峰值测试不能代表真实音频播放总CPU。

主窗口页面懒加载/大列表虚拟化、麦克风端点回调替换轮询、采样工作线程异步退出需要单独的生命周期设计与测试，本轮没有改造。现有采样范围及定时通知语义保持。
