## 术语与目标范围

| 名称 | 实际含义 |
|---|---|
| 播放 / 录音 | 面向用户统一使用的术语；源码中的 Output / Input、Render / Capture 名称保留用于定位 |
| 系统默认设备 | 执行时的系统默认播放或录音设备；更改默认设备不等于重置应用单独保存的设备路由 |
| 指定设备 | 用户选定的真实设备 ID；即使它当前不是默认设备，也可直接调整其音量或静音 |
| 指定应用 | 保存进程名，执行时从已发现的音频应用中解析一个匹配 PID；不是对所有同名进程广播 |
| 当前应用 | 执行该步骤时按 SonicRoute 的统一“当前应用”规则选择，受固定 / 上次应用等设置影响，不能直接等同于触发应用或当前前台窗口 |
| 应用播放静音 | 修改目标 PID 的播放音频会话，其他应用保持各自状态 |
| 应用录音静音 | 修改目标 PID 可控制的录音会话；不是设备静音，不保证所有应用都支持 |
| 设备静音 | 修改整台播放或录音设备，使用它的其他应用也会受影响 |
| 全局麦克风静音 | 对本次发现的全部可用录音设备设置静音；没有为后续新接入设备建立持续拦截 |
| 全部应用操作 | 处理执行时发现的现有播放会话，不是持续策略，不会自动应用于以后新出现的会话 |

## 六种触发方式

每条规则选择一种触发方式。规则启用后才参加自动触发；各类触发都可以调用同一组动作。

| ID | 触发定义 | 配置内容 | 何时触发 | 容易混淆的边界 |
|---|---|---|---|---|
| 0 | 快捷键 `Hotkey` | 用户绑定的组合键或支持的鼠标输入 | 命中已注册的规则快捷键 | 编辑器要求填写快捷键；不要预设一组可能与用户现有绑定冲突的按键 |
| 1 | 应用启动 `AppStart` | `TriggerApp` 目标进程名 | 监测中该进程名由不存在变为存在 | 建立监听基线时已存在的应用不补触发；进程出现不表示音频会话就绪 |
| 2 | 切换到应用 `AppSwitch` | `TriggerApp` 目标进程名 | 前台 PID 变化并匹配目标进程名 | 不是开始播放或开始通话；同一 PID 内切换页面 / 窗口不能据此保证触发 |
| 3 | 应用退出 `AppExit` | `TriggerApp` 目标进程名 | 监测中此前存在的进程名消失 | 关闭窗口但仍留在托盘不算退出；还有同名进程时不算该进程名消失 |
| 4 | 定时 `Schedule` | 模式、时间、每周所选星期 | 到达所配置的本机时间 | 不是持续限制音量；关机 / 睡眠错过后不补执行 |
| 5 | SonicRoute 启动 `Startup` | 无额外触发参数 | 本次正常进程启动完成时派发一次 | 保存、刷新规则或重新打开界面不重触发；临时命令行执行不顺带运行它 |

应用启停按进程名集合变化判断，多进程软件应选实际需要监测的进程。运行期间的短暂事件和无法确认的进程状态不应当作可靠的通话开始 / 结束信号。

模型兼容空 `TriggerApp` 表示任意应用，但当前编辑器要求应用触发规则选择目标应用。后续设计按编辑器可配置能力描述。

### 定时细则

| 字段 / 行为 | 定义 |
|---|---|
| `ScheduleMode=0` | 仅一次：等待下一个到达的 `HH:mm`，今天已过则取明天；没有指定日期字段 |
| `ScheduleMode=1` | 每天：每天同一时间 |
| `ScheduleMode=2` | 每周：所选星期的同一时间，至少选择一天；星期数值为 0=周日至 6=周六 |
| `LastRunKey` | 以 `yyyy-MM-dd HH:mm` 记录已领取的调度时刻，避免同一时刻重复领取 |
| 仅一次停用时机 | 调度器领取并保存计划时即停用，之后才执行步骤；步骤失败也不会自动重试，不能写成“全部步骤成功后才停用” |
| 时间与恢复 | 使用 Windows 本机时间；时间变化、睡眠恢复及计划修改会重算下一次。过期不补跑；到期回调另有 2 分钟迟到容差，不应依赖它做补执行 |
| 等待方式 | 只等待最近一次到期的一次性计时器；没有每分钟扫描全部计划 |

## 直接执行入口

直接执行不是第七种触发类型。用户可以从规则列表运行、托盘收藏、命令行或“执行另一条规则”动作明确调用已有规则，无需等待其自动触发条件。`Enabled=false` 只关闭自动触发，不阻止这些明确调用。

新建时仍需满足编辑器对所选触发方式的必填要求。把规则加入托盘收藏不会把它转换为独立的“手动触发”类型。

命令行参数、冷启动行为、返回码和断开边界见 [命令行直接执行自动化规则](automation-command-line.md)。

| ID | 动作 | 参数与范围 |

| 31 | 增减全部应用播放音量 `AdjustAllAppsVolume` | `VolumeDelta`；分别在各会话原值上增减 |

## 规则与步骤字段

| 层级 | 字段 | 定义 |
|---|---|---|
| 规则 | `Id` / `Name` | 稳定身份 / 显示名称；规则调用保存 ID，改名不改变调用目标 |
| 规则 | `Enabled` | 是否参加自动触发；模型中普通新规则默认 true，现有模板草稿和复制的新规则默认 false |
| 规则 | `Trigger` / `Hotkey` / `TriggerApp` | 触发方式及其对应参数；触发应用与每步的目标应用是两个独立概念 |
| 规则 | `ScheduleMode` / `ScheduleTime` / `ScheduleWeekdays` / `LastRunKey` | 定时模式、时间、星期与防重复领取记录 |
| 规则 | `Actions` | 按顺序保存的步骤列表；旧单动作字段只是兼容入口 / 首步骤镜像 |
| 步骤 | `Action` | 本步动作 ID |
| 步骤 | `TargetApp` | 指定目标进程名，不保存 PID |
| 步骤 | `TargetDeviceId` | 目标设备 ID；只有应用路由动作允许选择“跟随系统默认”虚拟项 |
| 步骤 | `TargetRuleId` | 被调用规则的 ID |
| 步骤 | `Volume` / `VolumeDelta` | 绝对音量 0–100 / 相对变化 −100–100 个百分点，结果限制在 0–100 |
| 步骤 | `Muted` | true=静音，false=取消静音；仅明确设置静音的动作使用 |
| 步骤 | `DelayMs` | 执行本步前等待的毫秒数，0=立即；固定等待，不检测就绪状态 |
| 步骤 | `StopOnFailure` | 本步失败后是否停止本规则后续步骤；默认 false |
| 步骤 | `OsdTitle` / `OsdText` | 自定义屏幕提示文字 |
| 步骤 | `LaunchItems` / `LaunchMode` | 启动项路径、打开方式；模式 0=全部、1=随机一个 |
| 步骤 | `ProgramPaths` | PowerShell 输入；在启动程序动作中只保留旧配置兼容路径镜像 |

## 执行顺序与失败处理

1. 每次开始执行时复制步骤列表，按顺序执行；每步先等待自己的 `DelayMs`，再执行动作。
2. 同一规则正在执行时拒绝重入，不叠加执行。应用事件的待办会合并并在执行前复核资格，过时的前台切换请求可能被丢弃。
3. 不同规则没有全局事务或统一锁序：应用事件队列自身串行，启动规则逐条派发，但快捷键、定时、命令行等独立入口仍可能让不同规则并发。
4. `StopOnFailure=false` 时记录失败并继续；true 时只在该步失败后跳过本规则剩余步骤。此前已成功的修改保留。
5. “执行另一条规则”按 ID 读取已有规则并等待其结果。目标停用仍可明确调用；目标缺失、忙碌、失败、循环或调用过深会使调用步骤失败，再按父步骤的停止设置处理。
6. 循环调用被拒绝，最多允许 16 层规则调用路径。没有“失败后自动重新运行整条规则”的通用机制。
7. 程序退出会取消执行生命周期和可取消的等待；已完成的音频修改、已启动的外部程序不会因此撤销。

设计重复触发场景时优先用“设置到某值 / 设置静音状态”，少用“切换”或反复增减。关键设备步骤可选择失败后停止；非关键应用缺失是否继续，由场景目的决定。

## 当前能力边界

| 希望达到的效果 | 当前实际能力 |
|---|---|
| 恢复操作前的所有状态 | 没有原生状态快照和事务回滚；“回到日常”只能设置用户指定的预设值 |
| 耳机插入后自动切换 | 没有设备接入 / 拔出规则触发器；可先设计为用户快捷键或托盘收藏 |
| 通话开始 / 结束自动降音量 | 没有真实通话状态触发器；应用启动、切前台和退出都不等同于通话状态 |
| 始终限制某设备最大音量 | 设置音量是一次动作，没有持续音量上限策略 |
| 应用启动后一定成功路由 | 进程已启动仍可能没有可解析的音频会话；固定延时不能保证成功 |
| 所有应用都能单独静音麦克风 | 依赖可控制的目标录音会话，不能保证所有软件支持，且不回退为全设备静音 |
| 任何失败都完全没有改变 | 步骤或批量操作可能已部分成功，没有自动撤销 |
| 把一组配对规则一次导入 | 当前产品模板是一份单规则草稿；新场景的规则组合尚未实现 |
